# ASR 语音上行端点验证（`POST /api/v1/asr/chunk`）

> 日期：2026-09-14
> 环境：本机（Windows），CPU 推理（funasr 1.4.12 / paraformer-zh-streaming / torch 2.14.0+cpu）
> 被测路径：前端同路径（经 vite proxy `localhost:5173` → 后端 `127.0.0.1:8010`）
> 输入：`data/testset/audio/*.wav`（固定测试集真实音频，16kHz 单声道）
> 分片：9600 样本 = 600ms/片（与 V-03 的 chunk_stride 口径一致）

## 验证方式

按 600ms 分片逐片 POST（`seq` 递增），最后一片带 `end=true` 触发收尾（is_final）。
这复现了浏览器端 AudioWorklet 的调用序列（`useMicCapture.ts` 用同一分片粒度）。

## 口径与结论

- **单分片往返 ≈ 250ms**（含 HTTP + 600ms 音频的模型推理；扣除模型加载后的样本：
  t1-02 5 片 1302ms、t2-01 5 片 1378ms、t2-02 5 片 1035ms）
- 与 V-03 的"单块 166ms"差异来自 HTTP 往返与分片封装，同一数量级
- 识别文本与测试集设计意图一致（运费咨询 / 发货时效 / 退货流程 / 退款到账 / 多轮长句 / 短指令）
