# ASR 麦克风链路核对与端点阈值标定（`asr_mic_check`）

> 日期：2026-09-15
> 环境：本机（Windows 11），离线试验（无麦克风、无浏览器）
> 被测对象：`frontend/public/worklets/mic-processor.js`、`frontend/src/hooks/useMicCapture.ts`（ADR-004 前端 VAD）、固定测试集 `data/testset/audio/`
> 脚本：`backend/eval/verify_asr_endpoint.py`（node 探针 `backend/eval/mic_rms_probe.mjs` 忠实执行前端 worklet 原文件）
> 原始数据：`backend/eval/reports/asr_endpoint_calibration.json`

**一句话结论**：2026-09-15 两项前端缺陷**已修并验证** ——
① 固定静音阈值在底噪 ≥0.012 的环境下会让端点**永不触发**（用户说完数字人不响应、静默失效）→ 改为自适应阈值；
② 前端 RMS 口径错误（**低估 19%**、**完全漏检 50ms 级瞬态**）→ 改为整帧口径，worklet 与理论值一致性 **0.993~1.000**；
打断判据同时改为「相对底噪 + 连续 200ms 确认」。另修复了 **FR-06 的结构缺口**：播报期间此前根本没有采集麦克风，插话永远检测不到 → 新增 `barge` 监听模式。
**剩余风险**：数字人外放是否触发自打断（依赖浏览器 AEC）离线无法验证，**必须真人实测**（§5 第 4 项）。

## 1. 端点阈值标定（SILENCE_RMS=0.012 / SILENCE_MS=1200）

场景由固定测试集音频（`t1-01.wav` 人声、"你们家运费怎么算"）+ 合成底噪构造。
有声段用自适应门限（帧能量 20 分位 ×3）自行检测，**不依赖文件时长**。

| 场景 | 底噪 | 固定阈值（改动前） | **自适应阈值（2026-09-15 起）** | 判定 |
|---|---|---|---|---|
| 干净语音（基线） | 0.002 | 3.1s | 3.1s | OK（有声段结束 1.94s + 1.2s ≈ 3.1s，符合设计） |
| 中等底噪 | 0.006 | 3.1s | 3.1s | OK |
| 临界底噪（旧余量仅 9%） | 0.011 | 3.1s | 3.1s | OK |
| **底噪高于阈值** | **0.015** | **无端点 ❌** | **3.1s ✅** | 固定阈值下 **NO_ENDPOINT**（用户说完不收尾）；自适应后恢复正常 |
| 句中停顿 1.0s | 0.002 | 4.1s | 4.1s | OK（<1.2s 不误断句） |
| 句中停顿 1.5s | 0.002 | 2.5s | 2.5s | SHORT_TAIL（>1.2s 在停顿处收尾，**句子被切断**——设计取舍，未改） |
| 纯底噪无人声 | 0.002 | 1.2s | 1.2s | OK（录音后 1.2s 自动收尾，属设计） |

**自适应机制（`useMicCapture.ts`）**：底噪估计 `floor` **只降不升**（min 跟踪器）——
降 = 捕捉安静帧得到真实底噪；不升 = 说话与瞬态永远顶不高它。
判定阈值 = `max(floor × 3, 0.004)`，取值区间 **[0.004, 0.036]**。

**为什么是「只降不升」而不是「缓升」**：缓升跟踪器（如 `floor *= 1.02`）在持续说话时会把 floor 逐步推高，
最终把语音本身判成静音（阈值失控）。而无参数、单调下降的 min 跟踪器不存在这个失效模式。

**要点**：
- 固定阈值**没有留出安全余量**：按"环境噪声 0.002~0.008"推断的 0.012，在真实环境（风扇/空调/街道）上很容易越线，
  越线后端点判定**静默失效**（不报错，只是数字人不响应）。自适应版本已消除该失效。
- 仍存在的边界：① 底噪 >0.036 的极吵环境（阈值上限）仍会失效；② 用户说话中途停顿 >1.2s 会被切句
  （设计取舍，不是 bug，但演示话术要知道这条边界）。

## 2. 前端 RMS 口径核对（关键发现）

`mic-processor.js` 每 1600 样本（100ms）发一帧，但：

```js
let sum = 0;                                    // ← 每次 process() 调用重置
for (let i = 0; i < ch.length; i++) {           // ch.length = 128（render quantum）
  sum += ch[i] * ch[i];
  this._buf[this._n++] = ch[i];
  if (this._n === FRAME) {
    const rms = Math.sqrt(sum / ch.length);     // ← 分子只有本次调用的样本，分母固定 128
    ...
```

`sum` 只累加**当次 `process()` 调用**的 128 样本，而 `1600 ÷ 128 = 12.5` 不是整数，所以帧边界总落在某次调用的中间 —— 实际参与计算的是**该调用中到帧边界为止的约 65 个样本（≈4ms）**，且分母写死 128。后果（`verify_asr_endpoint.py` 用 node 忠实执行原文件实测）：

| 场景 | current rms 均值 / 峰值 | fixed（整 100ms 窗口） | 比值 |
|---|---|---|---|
| 语音（干净） | 0.02866 / 0.26828 | 0.03522 / 0.25701 | 0.814 |
| 语音（底噪 0.011） | 0.03450 / 0.26849 | 0.04166 / 0.25718 | 0.828 |
| **50ms 瞬态脉冲** | **0.00169 / 0.00219** | **0.00549 / 0.14143** | **0.308** |
| 模拟回声（另一段语音） | 0.04117 / 0.25738 | 0.05662 / 0.24055 | 0.727 |

- **系统性低估 19%**（语音场景 0.81~0.83）：等于 `SILENCE_RMS=0.012` 实际按 ~0.0148 的有效门限在判静音。
- **瞬态完全漏检**：同一个 50ms、幅度 0.2 的脉冲，current 看到 0.0022（=底噪水平，等于没看见），fixed 看到 0.1414。原因是脉冲落在两次触发点之间时，其能量被 `sum` 的每次调用重置丢掉了。
- **双向影响，不要一刀切当 bug 修**：
  - 有利面：瞬态噪声（敲键盘、咳嗽、碰麦克风）**不会**误触发打断；fixed 版则会（0.1414 > 0.036 判据）。
  - 不利面：用户**短促的插话**（半个字、单音节）可能被完全忽略；且标度是错的——任何基于 `rms` 的阈值判断都建立在 19% 偏移的标尺上。
  - 结论：若要修（改成整 100ms 窗口），**必须同时给打断判据加去抖**（如"连续 ≥200ms 高于阈值"），否则误打断概率会上升。

### 2.1 修正与验证（2026-09-15 已落地）

`mic-processor.js` 改为**帧内累加**（`this._sumSq` 随样本累加、发帧时清零，`rms = √(sumSq / FRAME)`，分子分母同为整帧口径）。

**验证方式**：`mic_rms_probe.mjs` 用 node **忠实执行 worklet 原文件**（不手抄逻辑）取序列，与 Python 实现的整帧窗口 RMS 逐场景比对：

| 场景 | 修正前 worklet/理论 | **修正后 worklet/理论** |
|---|---|---|
| 语音（干净） | 0.814 | **0.9996** |
| 语音（底噪 0.011） | 0.828 | **0.9997** |
| **50ms 瞬态脉冲** | **0.308** | **0.9976** |
| 模拟回声 | 0.727 | **0.9998** |

比值恒为 ~1.000 即口径正确（残余 0.3% 来自 float32 累加精度）。**这个比值本身是回归闸门**：后续任何人改 worklet，重跑本脚本即可发现口径漂移。

## 3. 打断链路（FR-06）：判据、去抖，以及"谁能打断"

### 3.1 判据变更

| | 判据 | 去抖 |
|---|---|---|
| legacy（改动前） | 固定 `rms > 0.036`（= SILENCE_RMS×3） | 无（单帧 100ms 即触发） |
| **target（当前）** | `rms > max(底噪估计×8, 0.03)` | **连续 2 帧（200ms）** |

改成相对底噪的理由：固定 0.036 在噪声环境过松（噪声就能打断）、在安静环境过紧。去抖的必要性由数据决定 ——
RMS 修成整帧口径后，50ms 级瞬态**会**命中瞬时判据（实测 0.1414 > 0.03）。

### 3.2 离线实测效果

| 场景 | legacy 命中帧 / 触发 | **target 命中帧 / 触发** |
|---|---|---|
| 50ms 瞬态脉冲（敲键盘/咳嗽） | 1 / **1（误打断）** | 1 / **0 ✅ 去抖消除** |
| 模拟数字人外放（另一段 TTS 音频） | 37 / 37 | 37 / **17**（减少约一半，仍会打断） |
| 用户正常说话 | 命中（应触发） | 命中（应触发） |

### 3.3 判据的本质与防线

- 判据**不能区分"用户插话"与"数字人自己外放"**——只要有人在说话就命中。它实际是**"有声音检测"，不是"插话检测"**。
- 现有防线**三层**：① 前端 `state !== 'speaking'` 门（非播报态不响应）；② 触发后 2s 节流；③ **AEC（回声消除）**。
  三层**都在前端**，后端无保护。
- 因此 **AEC 是这个设计成立的前提**。`getUserMedia({echoCancellation: true})` 已开，但浏览器 AEC 在不同设备/扬声器音量下差异很大 ——
  **离线无法验证，必须人工实测**（§5 第 4 项）。若实测证明会自打断，ADR-004 的"P2 评估 VAD 迁后端"就有了硬依据。

### 3.4 结构缺口修复（2026-09-15）

此前 `useMicCapture` 在静音端点后即 `stop(true)` 释放 MediaStream，而 `startMic` 只由用户手动 toggle 触发
→ **数字人播报期间前端根本没有采集**，`onBargeIn` 不可达，自动打断形同虚设（只剩手动按钮）。

现新增 `barge` 采集模式（`useMicCapture.ts`）：`state === 'speaking'` 时自动开启一路**只跑 VAD** 的采集
（**不上行音频**——否则数字人自己的声音会被当作"用户说话"送进 ASR），离开 speaking 即释放。
该修复的**行为验证必须真人执行**（§5 第 3、4 项）。

## 5. 待人工实测清单（必须真浏览器 + 真麦克风，离线无法覆盖）

> 前 4 项是 `asr_endpoint_check.md`「未覆盖」三节的落地。建议逐项记录到 `backend/eval/reports/asr_mic_check.json`。

| # | 项目 | 步骤 | 判据 |
|---|---|---|---|
| 1 | 麦克风闭环（FR-01） | 起后端 `127.0.0.1:8010` + 前端 `5173` → 点说话 → 说 T1-01「你们家运费怎么算」 | 界面出现识别文本且与测试集一致；数字人回答；记下「首个 tts_audio」延迟读数 |
| 2 | 端点标定（真实环境） | 分别在①安静房间 ②开风扇/空调/临街窗 ③播放背景音乐 三种环境下各说 10 句（T1/T2 类），说完整句 | 记录：提前被切句次数 / 说完不收尾次数。**若第②③种环境出现"说完不收尾"，即命中本报告 §1 的阈值失效**——需要调 `SILENCE_RMS`（见下） |
| 3 | 打断响应（FR-06） | 数字人播报时插话「等等，那退货呢」 | 数字人停止播报并转向新问题；主观响应无感（<200ms 由脚本侧另行测量） |
| 4 | **回声自打断（关键）** | 数字人播报时**保持不说话**，外放音量开到演示档位，观察 10 轮 | 不应该出现任何打断/状态跳到 interrupted。**离线已证**：若无 AEC，外放音频会命中打断判据 37 帧、触发 17 次（§3.2）——所以这一项验的就是 AEC。**若出现自打断 → 触发 ADR-004 的 P2 评估**（VAD 迁后端 / 加后端侧回声处理），或调高 `BARGE_MULT`/`BARGE_FRAMES` |
| 4b | 监听模式本身 | 数字人播报时确认存在一路麦克风监听（`monitoring`），且**不上行 ASR**（后端日志不应出现新的 `/asr/chunk`） | 监听开得起来；播报期间后端 ASR 端点无新请求（否则会把数字人的声音识别成用户说话） |
| 5 | 模型预热 | 演示前先打一次 `/api/v1/asr/chunk` | 避免首次请求等 FunASR 模型加载 ~22s（RUNBOOK 坑 8） |

**阈值调整建议**（若 §5 第 2 项发现环境失效）：
把 `SILENCE_RMS` 从固定值改为**启动时自适应**——录制前 0.5s 采环境底噪，取 `max(底噪×3, 0.012)`；`SILENCE_MS` 保持 1.2s。改这个需要同步更新 SPEC §7 与 DESIGN-打断 §4.1（当前两处已写"前端标定，当前 1.2s"）。

## 6. 未覆盖 / 不适用

- **离线试验用的是合成底噪**（均匀分布白噪声），真实噪声有频谱结构（空调低频、键盘瞬态、多人说话），本报告的门限余量结论在真实环境下**只能作为上界参考**。
- **浏览器 AEC 效果未验证**（§3 结论的前提），也无法离线验证。
- **重新采样链路未覆盖**：`useMicCapture.ts` 的 `resample()` 兜底（AudioContext 未给 16k 时）在本次试验中未触发——本次直接用 16k 数据。
- **真实麦克风的 100ms 帧调度抖动**未测（离线按精确 100ms 步进）。
- `display`/`AudioWorklet` 在不同浏览器（Chrome/Edge/Firefox）的行为差异未测。
