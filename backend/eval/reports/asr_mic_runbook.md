# ASR 真人链路实测操作卡（`asr_mic_runbook`）

> 日期：2026-09-15
> 用途：把 `asr_mic_check.md` §5 的清单变成可照着做的步骤。
> **为什么必须由人做**：离线脚本能验算法（阈值/口径/判据），验不了**真实麦克风、浏览器 AEC、回声是否自打断**。
> 做完把最后的「记录表」填好贴回对话，我据此回填 `docs/eval-history.md`。

---

## 0. 前置（一次性，按顺序）

```bash
# ① 起服务（双击，或 git-bash 里：）
./start.bat            # 后端 :8010 + 前端 :5173 + 自动开浏览器 /console

# ② 预热 ASR 模型（关键：不预热第一条语音会等模型加载，甚至触发 ASR_TIMEOUT）
python backend/eval/prewarm_asr.py
#    期望：第 2 片 < 1000ms（实测 362ms）。若报"后端不可达"，说明 ① 没起来。

# ③ 浏览器里按一次 Ctrl+Shift+R（硬刷新）—— worklet 在 public/ 下会被缓存，
#    不硬刷你测的还是旧的 mic-processor.js
```

⚠️ 三条注意：
- **口型需要云 GPU**：`lip_service.reachable=false` 时只有声音没有口型画面。要看口型，先开 AutoDL 实例，再跑 `bash backend/deploy/restore-cloud-lip.sh <SSH端口>`（见 RUNBOOK §3.12）。
- **实测期间别重启后端**：重启会丢掉已加载的 ASR 模型，要重新预热。
- 浏览器地址用 `127.0.0.1:5173`（不要 `localhost`，本机名字解析约 2s/次，RUNBOOK 坑 20）。

## 1. 麦克风闭环（FR-01）

| | |
|---|---|
| **操作** | 点界面上的麦克风按钮 → 说「**你们家运费怎么算**」→ 停住不说话，等 ~1.2s 自动收尾 |
| **看什么** | ① 界面上实时识别的文字；② 数字人是否回答（有声音）；③ 延迟瀑布图里「本轮」的读数 |
| **判据** | 识别文本与测试集一致（「你们家运费怎么算」）；数字人正常回答 |
| **记录** | 识别文本：`______`；是否有回答：`是/否`；首响读数：`___ms` |

## 1b. 准确率采集与复盘（真人样本 → 字准率报告）

> **为什么必须单独做**：固定测试集音频是 **TTS 合成的**（干净、无噪声），流式模型在它上面近乎全对
> （7/7）——所以"真机感受不好"用那批音频**根本定位不了**。必须留下真实麦克风的样本。

**① 采集（后端要带开关，`start.bat` 不带）**

```bash
cd backend
ASR_DEBUG=1 PYTHONPATH=src .venv/Scripts/python.exe -m uvicorn api.routes:app --host 127.0.0.1 --port 8010
# 前端照常：cd frontend && npm run dev
```

**② 照 `docs/eval/EVAL-测试集定义.md` 的顺序逐条念**（从 T1-01 开始；一条一次语音会话：
点"说话"→ 念 → 停顿等自动结束）。每轮结束自动落盘：

```
backend/eval/reports/asr_capture/<时间>_<会话>.wav   ← 完整音频（可回放核对）
backend/eval/reports/asr_capture/<时间>_<会话>.json  ← 识别文本 + 时长
```

**③ 复盘**

```bash
cd backend/eval && ../.venv/Scripts/python.exe verify_asr_mic_accuracy.py
#   → 逐条 期望/识别/字准率 + 总体字准率 + 最差 5 条 + reports/asr_mic_accuracy.json
../.venv/Scripts/python.exe verify_asr_mic_accuracy.py --start T1-02   # 中途接着念
```

**④ 判读**

| 结果 | 下一步 |
|---|---|
| 字准率 **≥95%** | 准确率不是主要矛盾 → 问题在**交互节奏**（静音等待 1.2s / interim 每 600ms 才刷 / 手动结束） |
| **<95%** 且错例集中在领域词（包邮/运费/尺码） | 上**热词表** |
| **<95%** 且普遍错 | **two-pass**（端点后用离线模型整句重识别）——先用 `verify_asr_models.py` 确认离线模型确实更准 |

> 采集目录**不要提交进仓库**（真人语音），只提交报告里的数字。

## 2. 端点阈值（真实环境，验自适应）

| | |
|---|---|
| **操作** | 在 **3 种环境**下各说 5 句完整话（用固定测试集 T1/T2 的句子）<br>(a) 安静房间　(b) 开风扇/空调/临街窗　(c) 播放背景音乐 |
| **看什么** | ① 有没有「话没说完就被切句」（提前收尾）→ 说明阈值偏低<br>② 有没有「说完了数字人不响应」→ 说明阈值偏高（**上轮修的就是这个**） |
| **判据** | 三种环境都**不出现**上面两种现象 |
| **记录** | (a) 提前切句 `_次` / 不收尾 `_次`；　(b) `_次` / `_次`；　(c) `_次` / `_次` |

> 若 (c) 出现「不收尾」：多半是背景音乐太吵。可以先把音乐音量降到正常再试；仍失败就把现象告诉我，
> 我按实测数据调 `FLOOR_MULT` 或阈值上限。

## 3. 播报中插话（FR-06 核心，这轮新修的能力）

| | |
|---|---|
| **操作** | 提一个问题让数字人开始回答 → **它开始说话后 1 秒内**插话「**等等，那退货呢**」 |
| **看什么** | ① 数字人是否**立刻停下**；② 顶部状态条是否走 `speaking → interrupted → listening`；③ 停完后是否回答新问题 |
| **判据** | 能停下 + 状态条按上述顺序走完 + 转向新问题 |
| **记录** | 是否停止：`是/否`；状态条顺序：`对/不对`；停后是否答新问题：`是/否` |

> 这条是**这轮才真正具备**的能力：在此之前播报期间前端根本没有采集麦克风，插话不可能被检测到。

## 4. 播报中你别说话（AEC 回声，最关键的一条）

| | |
|---|---|
| **操作** | 让数字人说一段**较长**的回答（问 T5-02「充电宝快充+兼容+上飞机」这类长句），**期间你完全不说话**，外放音量调到你会用来演示的档位。重复 **5~10 轮** |
| **看什么** | 有没有出现**自动打断**（数字人自己说到一半停住、状态条跳到 `interrupted`） |
| **判据** | **0 次**自打断 |
| **记录** | 轮数 `___`；自打断次数 `___`次 |

> **为什么这条最关键**：离线试验已证——**若不依赖 AEC，数字人自己的外放音频会命中打断判据 37 帧、触发 17 次**。
> 也就是说这一条验的就是浏览器的回声消除（`echoCancellation: true`）。
> **若出现自打断**：告诉我，我调 `BARGE_MULT`（8→12）或 `BARGE_FRAMES`（2→3），
> 或者这成为 ADR-004「P2 评估 VAD 迁后端」的硬依据。

## 4b. 监听模式没在上行音频（防"数字人自己被识别成用户"）

| | |
|---|---|
| **操作** | 播报期间看**后端那个最小化的窗口**日志（`dh-backend-8010`） |
| **看什么** | 有没有**新的** `POST /api/v1/asr/chunk` 请求 |
| **判据** | 播报期间**没有**新的 ASR 请求（只有你说话那一批） |
| **记录** | 播报期间是否出现新请求：`有/无` |

## 5. 出问题时的排查顺序

| 症状 | 先查什么 |
|---|---|
| 识别文本为空或完全不对 | AudioContext 采样率回落（RUNBOOK 坑 10）→ 开浏览器 F12 console 看有无 resample 相关输出；`useMicCapture.ts` 有降采样兜底但需确认 |
| 说完不收尾 | 环境底噪过高 → 跑 `python backend/eval/verify_asr_endpoint.py` 看标定；把环境告诉我 |
| 播报中自己打断自己 | AEC 不足（§4）→ 调高 `BARGE_MULT`/`BARGE_FRAMES` |
| 第一次说话等很久 | 忘了预热（`prewarm_asr.py`） |
| 只有声音没有口型 | 云 GPU 没开 / 隧道没起（跑 `bash backend/deploy/restore-cloud-lip.sh <SSH端口>`，`health.lip_service.reachable` 应为 true） |

## 7. 这一卡覆盖不了什么

- **不影响结论的已知边界**：句中停顿 >1.2s 会切句（设计取舍，未改）；浏览器/设备组合无法穷举（本卡只验你演示用的那一台）。
- **口型与音画同步**不属本卡范围（口型依赖云 GPU，另有 ADR-006 待补测项：单片生成耗时 <1000ms）。
- 录到的音频**不要**提交进仓库（只提交这张表的数字）。
