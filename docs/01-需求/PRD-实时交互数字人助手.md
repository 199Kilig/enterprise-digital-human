## 1. 背景与要解决的问题（HUMAN）

数字人行业已从"内容生成"（离线制作口播视频）走向"实时交互"（数字人与用户实时对话）。但当前开源级联方案的工程落地存在三个普遍痛点：

1. **延迟**：用户说完话到数字人开口，全链路（语音识别 → 大模型 → 语音合成 → 口型驱动 → 渲染）串行累加，业界开源方案首包普遍在秒级（约 3s），交互体验"像电话延迟"。
2. **音画同步**：流式语音合成输出与口型驱动帧的时钟对齐难；用户中途插话时数字人无法及时停止。
3. **高并发与成本**：口型驱动依赖 GPU 推理，单路对话即占用大量显存，多路并发时成本不可控。

本项目从 0 到 1 构建一个评估驱动的实时交互数字人助手：语音输入 → 语音识别 → 对话大脑 → 流式语音合成 → 口型驱动 → 渲染播放，全链路自研编排，以固定测试集 + 同口径回归证明"每次优化可量化归因"。

目标场景：**企业网页客服/导购数字人**——顾客语音提问，数字人语音回答并带口型动作（形象使用通用虚拟形象，不做真人克隆）。对话内容覆盖售前售后（运费/退货/商品信息等），多轮对话，支持用户插话打断。

## 2. 目标与非目标（HUMAN）

### 目标
| 维度 | 目标 |
|---|---|
| 业务目标 | 面向电商零售客服场景，交付可实时对话的数字人助手（语音输入 → 语音+口型输出） |
| 能力目标 | 实时系统工程能力：延迟预算分解、流式流水线并行、音画时钟对齐、VAD 打断、GPU 推理服务化 |
| 工程目标 | 五维评估体系（延迟/音画同步/质量/稳定性/并发）全部可复现，数字有脚本背书 |

### 非目标（明确不做，防范围蔓延）
- ❌ 训练/微调口型、语音识别、语音合成模型（使用开源模型，工程重点是编排与优化）
- ❌ 端到端音视频生成模型（研究前沿，工程岗不碰）
- ❌ 3D 超写实形象建模（图形学领域）
- ❌ 移动端/小程序优化（浏览器 WebRTC 即可）
- ❌ 音色克隆（有余力再议）

### 2.3 功能需求范围（HUMAN）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-01 | 语音输入：流式语音识别（说话即可，不用等说完） | P0 |
| FR-02 | 对话大脑：大模型/智能体编排，统一模型供应商抽象（云端优先，本地兜底） | P0 |
| FR-03 | 语音合成：流式输出（首包即播，不等完整音频） | P0 |
| FR-04 | 口型驱动：开源口型模型（文本/音频 → 口型视频帧） | P0 |
| FR-05 | 渲染播放：浏览器 WebRTC | P1 |
| FR-06 | 打断：VAD 检测用户插话 → 停止当前语音 → 转向聆听 | P1 |
| FR-07 | 延迟打点：全链路每段计时（听/想/说/演），可回放 | P0（差异化核心） |
| FR-08 | 评估工具链：固定测试集 + 回归脚本 + 指标台账 | P0（差异化核心） |
| FR-09 | 配置中心：模型供应商/参数可切换（config.yaml） | P1 |
| FR-10 | 知识库接入（演进方向 ⚠️ 是否早期接入待定）：对话大脑可检索企业内部知识库（制度/售后政策等文档知识）；MVP 阶段先直连大模型 | P2 |

**非功能需求**：端到端延迟 < 2s、TTFT < 1s（⚠️ 建议值，实测后修正）；连续对话 30 分钟不掉帧 ⚠️；记录单次对话 token 与 GPU 成本；配置中心化、模型供应商可切换。

## 3. 验收标准（MUST）

- [ ] 端到端延迟（用户说完 → 数字人开口）< 2s ⚠️（建议值，实测后修正）
- [ ] TTFT（首个语音包）< 1s ⚠️（建议值）
- [ ] 音画时差 < 50ms（测量方法：自研脚本 + 人工抽检，方法本身要能讲）
- [ ] 打断响应 < 200ms（用户插话 → 数字人停止）
- [ ] 单卡并发 N 路 ⚠️（云 GPU 实测后定，先记录 1 路基线）
- [ ] 固定测试集 20-30 条 + 同口径回归台账（量化指标见评估台账对应行）
- [ ] README：架构图 + 延迟瀑布图 + 指标表 + 30 分钟 demo 脚本

## 4. 风险清单（MUST）

| 风险 | 影响 | 缓解 |
|---|---|---|
| 口型效果"像但假" | 体验不及预期 | 不吹效果，差异化在延迟/同步/并发；如实说明（行业通病） |
| 云 GPU 成本失控 | 预算超支 | 每周固定预算；实验完即释放；成本台账 |
| 流式语音合成时间戳不可用 | 音画同步方案受阻 | 启动后第一天验证；不可用则换合成方案或降级为"音频对齐" |
| 音画同步难量化 | 验收无依据 | 自研时差测量脚本先行，量化方法本身可讲 |
| 与外部并行任务冲突 | 进度延期 | P1 保底（跑通 + 第一个真实数字），P3 按"延迟→音画→并发"裁剪 |
| 设备/网络（WebRTC 穿透） | 联调受阻 | 本地 localhost 验证优先，NAT 穿透后置 |
