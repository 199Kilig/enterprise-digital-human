# ADR-001：开发与推理环境分工

> 文件名：`ADR-001-环境策略.md`
> 类型：adr
> 状态：已接受
> 读者：任何想知道"为什么这么选"的人（含 AI）
> 结论：本机做链路开发与调试，口型推理/并发实验在按小时租用的云 GPU 上进行

## 背景

实时交互数字人链路中的口型驱动模型（MuseTalk 类）需要 GPU 推理，且实时性要求高。本机为 RTX 3050（显存约 4-8G，算力有限），不足以支撑口型模型实时推理与多路并发实验；全程租用云 GPU 则成本不可控。

## 决策

我们将采用**双环境分工**：

- **本机（开发与调试）**：全链路代码开发、小模型验证（语音识别/语音合成轻量模型）、编排/状态机/前端调试、延迟打点框架搭建。
- **云 GPU（按小时租用，AutoDL 类平台）**：口型推理、FPS/显存记录、批处理/量化实验、并发压测、流式时序验证。

README 与交付物中如实标注"推理实验在云 GPU 完成"——这是工程常态，不回避。

## 被否方案

| 方案 | 否掉原因 |
|---|---|
| 全本机（3050） | 显存/算力不足以实时推理口型模型，并发实验无法进行 |
| 全云 GPU | 开发期长时间占用按小时计费资源，成本失控 |

## 后果

- 正面：成本可控（按需租用）；本机开发迭代快；链路代码与 GPU 无关部分可本地验证
- 负面：云上实验环境与本地环境不一致（依赖版本/CUDA），需要环境记录文档兜底；实验数据（FPS/显存）必须随实验即时落档，否则丢失
- 中性：面试/评审时需解释"为什么推理实验在云上"——如实说明环境约束即可
