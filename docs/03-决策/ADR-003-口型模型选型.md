# ADR-003：口型模型选型

> 文件名：`ADR-003-口型模型选型.md`
> 类型：adr
> 状态：已接受
> 读者：任何想知道"为什么这么选"的人（含 AI）
> 结论：口型驱动模型选 MuseTalk（开源、实时性主流、效果优于早期方案）

## 背景

口型驱动环节需要开源模型：输入文本/音频，输出与语音同步的口型视频帧，且要满足实时交互的延迟约束。候选开源方案包括 Wav2Lip（较早）、SadTalker（经典）、MuseTalk（2024 后开源）、EchoMimic 等。

## 决策

我们将选用 **MuseTalk** 作为口型驱动模型：开源、实时性好、社区活跃、效果优于 Wav2Lip 类早期方案，且与流式音频配合的时序调度有社区验证案例。

## 被否方案

| 方案 | 否掉原因 |
|---|---|
| SadTalker | 生成实时性弱，难以满足实时交互延迟要求 |
| Wav2Lip | 效果较旧（口型精度一般），实时性亦不占优 |
| EchoMimic 等 | 效果可能更优但部署/社区成熟度不如 MuseTalk，风险高 |

## 后果

- 正面：实时性达标路径清晰；社区案例多，踩坑可查
- 负面：口型效果仍属"像但假"水平（行业通病）——差异化不押在效果上，押在延迟/同步/并发与评估体系
- 中性：模型可替换（编排层已抽象），后续若出现更优开源方案可平移
