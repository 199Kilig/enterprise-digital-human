# ADR-007：教育场景门面与教师人格

> 文件名：`ADR-007-教育场景与教师人格.md`
> 类型：adr
> 状态：已接受
> 读者：想知道「这项目到底是客服还是教育」的人（含 AI）
> 注：本 ADR 第 1、2 条（首页学习域占位仪表盘及其标注方式）已由 **ADR-009** 修订——首页现为真实运行数据总览；其余条款继续有效。
>
> 结论：**对外演示改为教育场景**——前端交付「学习目标」门面（默认路由），后端对话人格由内联的客服「小顾」外置为可配置的教师「小奈」；但 **PRD §1 的目标场景仍记企业客服/导购**，教育是演示口径而非产品定位变更，人格可经 `config.yaml` 一键切回客服。

## 背景

- **PRD §1 的目标场景**：企业网页客服/导购数字人（售前售后、多轮、可插话打断）。PRD §3 的验收指标（端到端延迟、音画时差、打断响应、并发）与业务场景无关，属**链路能力**，不因场景调整而失效。
- **本轮需求变更**：项目所有者要求前端改为教育方向（学习目标仪表盘排版），并明确「没有的内容先进行一个占位」。
- **现状能力（已落地、非占位）**：真实链路 ASR（FunASR 流式）→ 前端 VAD 端点/打断 → DeepSeek 流式 → CosyVoice v2 流式合成（word 级时间戳）→ 口型 H.264 按音频分片；前端已有三视图（会话工作台 / 指标看板 / 评估台账），数据源为真实接口与 `backend/eval/reports/*.json`。
- **后端人格的原始形态**：客服提示词以模块级常量 `_BRAIN_SYSTEM_PROMPT` 内联在 `src/api/routes.py`，无配置入口、无第二人格、无可测边界。
- **后端能力缺口**：**没有任何学习域**（掌握度 / 任务 / 知识点 / 阶段目标）接口或存储；本轮不新建该域。

## 决策

1. **前端交付教育场景门面**：默认路由 `/` 为「学习目标」仪表盘（侧栏 = 助手卡 / 最近对话 / 学习工具 / 小奈 Pro / 工程视图；主区 = 本周学习目标、本周进度、今日任务、待加强知识点、阶段目标、智能建议）。设计 token 换成教育皮肤（主品牌粉 `#e8568f` 等色值由设计稿采样取得，见 `frontend/src/styles/tokens.css` 注释）。
2. **学习域数据单点占位并显式标注**：全部来自 `frontend/src/data/learning.ts`；界面必须标注「演示数据」（页头 badge + 每张卡片来源标签 + 建议卡注明建议未由真实诊断生成），避免被误读为已接真实业务数据。
3. **既有三视图全部保留、不砍能力**：`/console` 升格为「数字人对话」入口（首页「开始学习」「查看全部历史对话」跳转，走真实 SSE 链路），`/metrics`、`/ledger` 收进侧栏底部「工程视图」分组；`/tools/:key` 为学习工具占位页——写清依赖与实现要点，**不摆假界面**。
4. **对话人格外置为可配置模块**：新增 `src/brain/persona.py`，人格经 `config.yaml` 的 `llm.persona` 选择，`teacher`（默认，教育辅导「小奈」）/ `cs`（原客服「小顾」，文案一字未改）。未知人格**启动即抛错**，不静默降级（配置写错必须当场可见）。遵守 DESIGN §4.4 纪律：新增配置项的同批必须改代码真实读取它。
5. **PRD / DESIGN 场景口径本轮不改**：教育是演示门面。若转为正式产品定位，另开 ADR 并同步修改 PRD §1（场景）与 §3（验收表述）。
6. **人格提示词同时承担输出格式约束**（禁 Markdown / emoji / 动作说明、两句话以内、数学表达口语化）——理由与兜底见 ADR-008。

## 被否方案

| 方案 | 否掉原因 |
|---|---|
| 直接改 PRD 定位为教育 | 定位变更牵动全文叙事与验收口径表述，未拍板；本轮需要的是可演示的教育门面，不是重写需求基线 |
| 硬替换 prompt、删除客服人格 | 丢掉既有交付物，且失去场景 A/B 对照；同项目已按客服场景产出文档与实测证据 |
| 后端新增学习域接口（假数据接口或落 SQLite） | 后端无该域，属扩范围；假接口比集中占位更难被识别为「非真实」，反而增加误读风险 |
| 前端删除技术视图、只留教育界面 | 砍能力：延迟/音画同步/并发是本项目差异化核心，藏起来等于放弃证据链 |
| 学习数据照搬设计稿数值、不标注来源 | 会让评审与面试官误判为已接入真实学习域，属误导 |
| 人格写死在代码里（照旧内联常量） | 无法把「为什么是这个人格」与代码分离审查；切换场景要改 API 层 |

## 后果

- **正面**：教育场景可端到端演示（界面 + 真实语音对话）；人格可配置，客服场景随时回退；真实学习域接入时替换点收敛到 `learning.ts` 一个文件（页面只依赖其类型）；组件只引用 CSS 变量，换肤零改动波及。
- **负面**：同一仓库出现两套场景叙事（PRD 客服 / 界面教育），必须以本 ADR 作为解释锚点；`learning.ts` 是演示数据，**不得作为能力证据引用**。
- **中性**：`/console`、`/metrics`、`/ledger` 的视觉随教育皮肤 token 变化，组件结构未动；前端新增运行依赖 `recharts`（图表）。
- **风险**：人格与场景分叉后，若长期不收敛会形成「文档说客服、演示看教育」的口径漂移——在转为正式定位或彻底回退之前，本 ADR 是唯一仲裁依据。
