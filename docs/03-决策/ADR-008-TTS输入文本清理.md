# ADR-008：TTS 输入文本清理

> 文件名：`ADR-008-TTS输入文本清理.md`
> 类型：adr
> 状态：已接受
> 读者：排查「数字人为什么念出星号/表情」的人（含 AI）
> 结论：送 TTS 前对切句结果做一次清洗（`brain/text_clean.clean_for_tts`）——剥离 Markdown 标记、emoji、编号列表、链接与舞台说明，并把数学符号转口语；**只清洗送给 TTS 的那一份副本**，下发给前端的 token 与 `answer` 保持 LLM 原文。

## 背景

- **TTS 是「念」，不是「排版」**：LLM 输出面向人眼阅读，天然带 Markdown（`**加粗**`、`#` 标题、`-` 列表）、emoji、编号、链接与动作说明。这类字符送进 TTS 的结果不是报错，而是**念错**——星号被逐个念出、emoji 被念成符号名或触发怪音、`（停顿）` 被当正文读出来。属于「不报错但明显错误」的缺陷形态。
- **提示词约束只能减少、不能消除**：ADR-007 已在教师人格里写入输出格式约束（源头治理），但模型并不总听话；且用户可能显式要求「用 Markdown/emoji 回答」，此时约束必然失效。
- **实测（2026-09-19）**：直连 DeepSeek 强制要求「`#` 标题 + `**加粗**` + `-` 列表 + emoji + 链接 +（停顿）」的输出样本，未清理时含有 `#🧮`、`**先理解**`、`🍕⚡✏️🔗`、`https://…`、`（停顿）`；经清理后全部剥离，且逐句形态中有 4 处「整句只剩格式符号」的片段被判定跳过。
- **切句与清理的先后**：`brain/segmenter.py` 依据句末标点与长度阈值切分，**清理必须在切句之后**——提前清理会破坏标点，导致切分错位或丢字。

## 决策

1. **位置**：`src/api/routes.py` 的 `tts_consumer` 内——从 `sentence_q` 取句后立刻 `clean_for_tts(sentence)`，**非空才**调用 `_tts.stream(spoken, …)`。
2. **规则集**（集中在 `src/brain/text_clean.py`，可单测）：代码围栏与行内代码、标题 / 引用 / 分隔线 / 表格行 / 列表与编号标记、加粗斜体删除线、链接（保留链接文字、丢弃 URL）、emoji 与箭头等装饰字符、LaTeX 定界符；**舞台说明只删「整段命中动作词表」的括号内容**（≈30 个显式词）；数学符号 `× ÷ = ≈ √` 转口语（乘 / 除以 / 等于 / 约等于 / 根号）。
3. **保守边界**：中文标点与数学括号保持原样；不做数字→中文的数值口语化（属 TTS 前端文本规范化 TN 范畴，本轮不做）；不判断语义、不改写句子。
4. **清理后为空则跳过该句**：不占用 TTS 合成与口型推理（纯格式噪音片段不产生语音）。
5. **只清洗送 TTS 的副本**：`brain_token` 流与 `done.answer` 仍是 LLM 原文——前端按 Markdown 渲染气泡，历史记录保持一致。即「给人看的文本」与「给机器念的文本」在 TTS 入口处分离，不回写。
6. **可核对性**：离线诊断开关 `TTS_DEBUG=1` 打印**每句实际送合成的文本**（无论是否发生清理），使「喂给 TTS 的到底干不干净」成为可核对对象，而不是靠读代码推断。
7. **两层防护**：提示词约束（源头，ADR-007 §6）+ 本清理层（兜底）。任一层单独使用都不充分。

## 被否方案

| 方案 | 否掉原因 |
|---|---|
| 只靠提示词约束，不加清理层 | 模型不总听话；用户显式要求格式时必失效——缺陷会直接表现为「数字人嘴里念出星号」 |
| 要求 LLM 直接输出「可念文本」，前端也不渲染 | 同一 token 流要同时服务前端气泡与 TTS；迁就 TTS 会牺牲气泡可读性，且丢掉 Markdown 的结构信息 |
| 把清理结果回写前端显示 | 气泡失去排版、与本地历史/多轮上下文不一致；且把「人看的」与「机器念的」强耦合 |
| 删除所有括号内容 | 数学括号（如 `（3/4）`）是题目内容，删掉会把题念错——比念出「（停顿）」更严重 |
| 在切句器之前清理 | 切句依赖标点与长度阈值，提前清理会破坏切分（错位或丢字） |
| 引入第三方文本规范化库（TN） | 当前噪音形态明确且规则量小（十几条正则 + 两张词表），引库增加依赖与不可控行为；数值口语化等复杂场景留待有明确需求再评估 |
| 在 TTS 模块内部清理（`tts/cosyvoice.py`） | 会让 TTS 模块承担「理解 LLM 输出格式」的职责，且离线脚本/单测直接调用 TTS 时行为不一致——清理属于编排层的职责 |

## 后果

- **正面**：任意 LLM 输出形态下 TTS 只收到可念文本；规则集中且可单测（新增 18 个用例，覆盖 Markdown/emoji/链接/舞台说明/数学括号保留/空白折叠/幂等/空句跳过）；`TTS_DEBUG` 让清理结果可被逐句核对。
- **负面**：规则集需随新的噪音形态维护（正则与动作词表都是增量成本）；数学符号口语化是固定映射表，遇到新符号需补表。
- **中性**：口型分片与 word 时间戳基于清理后的文本，音频时钟不受影响（时间戳由 TTS 返回，切句结果与合成文本一一对应）；SSE 事件契约不变。
- **风险**：动作词表若过宽会误删正文（当前仅限约 30 个显式词，且要求括号内容**整段命中**）；后续若出现「正文被误删」的反例，必须补成单测并收紧词表。
