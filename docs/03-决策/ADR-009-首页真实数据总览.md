# ADR-009：首页改为真实运行数据总览

> 文件名：`ADR-009-首页真实数据总览.md`
> 类型：adr
> 状态：已接受
> 读者：想知道「首页那些数字从哪来」的人（含 AI）
> 结论：**默认路由 `/` 从「学习域占位仪表盘」改为「真实运行数据总览」**——卡片数据全部来自后端只读端点（`/api/v1/health`、`/api/v1/metrics`、`/api/v1/eval/ledger`）与本地真实对话历史；`frontend/src/data/learning.ts` 不再作为首页数据源。**本 ADR 修订 ADR-007 的第 1、2 条**，ADR-007 其余条款（教师人格、`/console` 真实链路、工程视图不砍）继续有效。

## 背景

- ADR-007 定下「教育场景演示门面」：首页 6 张卡片全部由 `frontend/src/data/learning.ts` 集中占位，界面显式标注「演示数据」（页头 badge + 每卡来源角标）。
- 项目所有者复核界面后的结论（原话）：**「前端界面中多数内容是占位卡片，无实际作用」**——占位卡片占满首页（6/6），可演示价值低于维护成本；演示/评审场景下「满屏查不到来源的数字」是负债而非资产。
- 系统实际具备的真实数据资产（本 ADR 落笔前实测）：
  - `GET /api/v1/health`：`api` 状态、`lip_service.{reachable, mode}`、`reports_present`(11)、`sessions_active`
  - `GET /api/v1/metrics`：读 `backend/eval/reports/*.json`，输出逐条验收指标 `dimension / metric / value / target / status(ok|warn|fail|pending) / scenario / env / source / measuredAt`
  - `GET /api/v1/eval/ledger`：`docs/eval-history.md` 原始台账
  - 浏览器本地：真实对话历史（`dh.console.session.v1`；侧栏「最近对话」已在使用）
- 约束：后端**没有**学习域接口或存储（ADR-007 已记录）；本轮不新建该域。

## 决策

1. **首页改为真实运行数据总览**。网格结构与视觉基线（等高网格、字号层级、卡片描边）不变，卡位与数据源一一对应：

| 卡位 | 新内容 | 数据源 |
|---|---|---|
| 本周学习目标 | 运行状态：API / 口型服务 / 活跃会话 / 评测报告数 | `GET /api/v1/health` |
| 本周进度（环形） | 验收达标率（达标项 / 总项） | `GET /api/v1/metrics` |
| 今日学习任务（跨两行） | 验收指标清单（按维度分组，逐条 value vs target） | `GET /api/v1/metrics` |
| 待加强知识点 | 未达标与待复测项（`status != ok`） | `GET /api/v1/metrics` |
| 阶段目标（折线） | 延迟版本对比（serial / pipelined / e2e 三条实测值） | `GET /api/v1/metrics` |
| 智能建议（跨全宽） | 链路诊断：由真实状态推导（如「口型服务未连接 → 数字人不会动嘴」） | `GET /api/v1/health` 推导 |

2. **保留一张对话入口**：首页保留通往 `/console` 的主入口按钮（真实 SSE 链路），文案「开始对话」。
3. **`learning.ts` 降级为工具页数据源**：不再是首页数据源；侧栏「学习工具」格与 `/tools/:key` 占位页继续引用它，口径按 ADR-007 第 3 条不变（写清依赖与实现要点，不摆假界面）。
4. **教师人格、`/console`、工程视图不变**：人格仍为 `teacher`（`config.yaml` 可切 `cs`）；`/metrics`、`/ledger`、`/studio` 保留在侧栏「工程视图」。
5. **首页数字必须可回溯**：每张卡片标注数据源（接口路径或报告文件名）；真实数据必须有明确的加载态与失败态，后端未起时显示错误而非静默回落假数据。

## 被否方案

| 方案 | 否掉原因 |
|---|---|
| 保留 6 张占位卡，只把「演示数据」标注做大 | 标注已经存在（页头 badge + 4 处卡片角标），项目所有者仍判定「无实际作用」——问题在数据本身，不在标注 |
| 新建学习域后端（假接口或落 SQLite） | 后端无该域，属扩范围；假接口比集中占位更难被识别为「非真实」（ADR-007 已否过一次） |
| 首页清空，只留对话入口 | 砍信息密度：11 份评测报告与链路实时状态摆在手边却不展示 |
| 半真半假混排（真实卡与占位卡同屏） | 评审时分不清哪张是证据、哪张是演示，反而放大误读风险 |
| 直接把工程视图的黑底表格搬上首页 | 首页是产品门面，沿用技术视图呈现会与已定的教育皮肤视觉基线冲突 |

## 后果

- **正面**：首页每个数字可回溯（可点进 `/metrics`、`/ledger` 查原始报告）；演示与面试被问「数据哪来的」时有 11 份实测报告兜底；首页从最弱一环变成证据入口。
- **负面**：教育叙事减弱——首页不再是「学习目标」而是「系统能力总览」；ADR-007 的「教育门面」表述需以本 ADR 为准解释，两文档并存时本 ADR 优先。
- **中性**：`learning.ts` 仍存在（侧栏工具格与 `/tools/:key` 使用）；首页新增对 `/api/v1/metrics` 的运行时依赖。
- **风险**：`/api/v1/metrics` 依赖 `backend/eval/reports/*.json` 存在；报告目录为空时达标率显示 `0/0`，需空态文案（已在实现中处理）。
