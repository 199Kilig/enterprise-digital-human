### 六、ASR 口径收口与离线标定（2026-09-15）

- [x] **文档口径收口**：SPEC v1.4 统一三处文档/实现冲突（静音阈值 2s → 前端标定 1.2s；`ASR_ERROR` 500 → 503；DESIGN §5.1 回填 ASR 首字实测）；DESIGN-打断 v1.1 同步
- [x] **端点阈值离线标定**：新增 `backend/eval/verify_asr_endpoint.py` + node 探针 `mic_rms_probe.mjs`（**忠实执行前端 worklet 原文件**，避免手抄逻辑出错）。结论：底噪 ≤0.011 收尾正常；**≥0.012（等于阈值）时端点永不触发** → 用户说完数字人不响应（证据：`eval/reports/asr_endpoint_calibration.json`）
- [x] **发现前端 RMS 计算偏差**：`mic-processor.js` 每 100ms 发帧，但 rms 只取当次 `process()` 调用（128 样本）的平方和、分母写死 128 → 实测**系统性低估 19%**、**完全漏检 50ms 瞬态**（0.0022 vs 修正版 0.1414）。影响是双向的，**未擅自修**（见待拍板项）
- [x] **打断响应后端侧测量**：新增 `backend/tests/test_interrupt_path.py`（6 条）+ `eval/verify_interrupt_path.py`；**median 4.43ms / p95 6.2ms / max 15.5ms**（50 次，ASGI 内存直连，不含前端 VAD 与网络）
- [x] **修掉真缺陷**：清理期（INTERRUPTED）重复收到打断时状态机正确忽略、但 HTTP 仍回 `interrupted` → 前端无法判断本轮打断是否生效。已区分返回 `ignored`（SPEC §5.2 v1.4 补全）
- [x] **ASR 实现收口**：`ASR_TIMEOUT` 落地（单块 >3s，事后判定不中断推理）；`AsrChunk.start_ms/end_ms` 修正为覆盖本次增量全部分块；删除空目录 `backend/src/vad/`
- [x] 单测 **40 → 50 passed**（新增打断路径 6 条 + ASR 时间戳/超时 4 条）

### 七、前端 VAD 修复：自适应阈值 / FR-06 监听 / RMS + 去抖（2026-09-15 本轮）

按 C → A → B 顺序执行，改动集中在 `frontend/src/hooks/useMicCapture.ts`、`frontend/public/worklets/mic-processor.js`：

- [x] **C 静音阈值自适应**：底噪用**只降不升**的 min 跟踪器（无参数、无缓升失控风险），阈值 = `max(底噪×3, 0.004)`。
      效果：底噪 0.015 场景由 `NO_ENDPOINT` → **端点 3.1s 正常收尾**，其余 6 场景无回归
- [x] **A 修复 FR-06 结构缺口**：新增 `barge` 采集模式 —— `state === 'speaking'` 时自动开一路
      **只跑 VAD、不上行音频**的采集（`ConsolePage.tsx` 加 useEffect 协调），离开 speaking 即释放。
      此前播报期间**根本没有采集**，插话永远检测不到（自动打断只剩手动按钮）
- [x] **B RMS 修正 + 打断判据去抖**：worklet 改为帧内累加整帧 RMS；判据 `max(底噪×8, 0.03)` + **连续 2 帧（200ms）**。
      效果：**worklet/理论 RMS 一致性 0.993~1.000**（修正前 0.814、瞬态 0.308）；瞬态误打断 **1 次 → 0 次**
- [x] 标定脚本升级为「一致性校验 + legacy/target 双配置对照」，并成为 worklet 口径的**回归闸门**
- [x] 证据：`npx tsc --noEmit` exit=0；`eval/reports/asr_endpoint_calibration.json`；报告 `eval/reports/asr_mic_check.md` §1~§3、§5
- [ ] **待真人实测**（脚本替代不了）：插话是否真能触发打断、数字人外放是否自打断（AEC）—— 清单见报告 §5 第 2/3/4/4b 项
