## 1. 触发场景（HUMAN）

数字人项目接上真实 LLM + 流式 TTS 后，出现一类**不报错但明显错误**的缺陷：LLM 输出是面向人眼排版的文本（`**加粗**`、`#` 标题、`-` 列表、emoji、链接），送进 TTS 后被逐个字符念出来——用户听到「星号星号重点星号星号」，或 emoji 被念成符号名/触发怪音，`（停顿）` 被当正文读出来。

面试讲背景：这类问题的特别之处在于**监控指标全绿**（延迟、丢包、时间戳都正常），只有"人听了"才发现错。做实时语音系统时，「给机器念的文本」和「给人看的文本」是两个不同消费者，必须显式分开。

## 2. 技术要点（MUST）

- **两类文本消费者的分离**：同一份 LLM token 流，前端要 Markdown 渲染气泡，TTS 要纯口语文本 → **只在 TTS 入口清洗，结果不回写**（ADR-008 决策 5）。
- **清理位置必须在切句之后**：切句器依赖句末标点与长度阈值分句（`brain/segmenter.py`），提前清理会破坏标点与长度，导致切分错位/丢字。
- **提示词约束不能替代清理**：模型不总听话；用户显式要求「用 Markdown/emoji 回答」时约束必然失效 → 约束管源头、清理管兜底，两层都要。
- **噪音形态清单**（按实际遇到整理）：Markdown 标记（标题/列表/引用/分隔线/表格行/加粗斜体删除线/行内代码/围栏）、emoji 与箭头等装饰字符、编号与项目符号、链接（应保留链接文字、丢弃 URL）、LaTeX 定界符、舞台说明（（停顿）（笑）（微笑）…）。
- **括号不能一概删**：数学/教学场景里括号是**题目内容**（如 `（3/4）`），一概删括号会把题念错——比念出「（停顿）」更严重。做法：只删「括号内容**整段命中**动作词表」的（词表约 30 个显式词）。
- **清理后为空要跳过该句**：单独一行的 `---`、只有 emoji 的行、被清空的列表符行——不应送合成（浪费 TTS 与口型推理，且可能产出异常音）。
- **正则边界坑①**：列表符规则必须要求**后跟空白或行尾**（`(?=[ \t]|$)`）。否则 `**加粗**` 行首的 `*` 被当列表符吞掉，产出 `分数*加减法` 喂给 TTS。
- **正则边界坑②**：行内强调不要写成一条通吃的 `(\*{1,3}|_{1,3})…\1`——`\1` 会在 `*` 与 `**` 之间回溯，把 `**分数**加减法` 匹成 `*分数*` + 残余 `*`。拆成 BOLD / ITALIC / UNDER_BOLD / UNDER_ITALIC 四条分别锚定。
- **可核对性**：清理效果必须能被**看见**，否则只能靠读代码下结论——用环境开关（`TTS_DEBUG=1`）打印每句实际送合成的文本。
- **边界（不做）**：数字→中文的数值口语化（`82%` → 百分之八十二）属 TTS 前端文本规范化（TN）范畴，需要数字与量词判断，不在本轮范围；不做语义改写与摘要。

## 4. 难点与解决（HUMAN）

**难点 1：清洗位置选在哪。** 最初想法是在 LLM 输出后立刻清洗（离源头最近）。读 `segmenter.py` 后发现切句依赖标点与长度阈值——提前清理会把 `。！？；` 之外的标记删掉、破坏切分节奏（可能把一句切碎或攒成超长句），于是把清理点放到**切句之后的 TTS 入口**（`tts_consumer` 内取句后、`_tts.stream()` 之前）。

**难点 2：正则写宽了一点点就出错。** 单测首轮就抓到两个真实缺陷（不是测试写错）：
① 列表符 `[-*+•·]` 匹配到 `**分数**加减法` 的行首 `*` → 输出 `分数*加减法`；修法是加后视条件 `(?=[ \t]|$)`。
② 一条通吃的强调正则把 `**分数**加减法` 匹成 `*分数*` + 残余 `*`（`\1` 在 `*` 与 `**` 间回溯）；修法是按标记长度拆成四条正则。
教训：**文本清洗规则必须有单测**，靠肉眼看输出极易漏掉边界残渣。

**难点 3：中文与数学场景的取舍。** 舞台说明（（停顿）（笑））必须删，但数学括号（（3/4））必须留——两者形式相同。解法是**显式动作词表 + 要求整段命中**，而不是"删所有括号"或"删所有中文括号"。
