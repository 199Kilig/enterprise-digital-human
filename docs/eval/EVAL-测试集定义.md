## 1. 文档目的

PRD §3 验收标准要求"固定测试集 20-30 条 + 同口径回归台账"。本文件定义测试集的**组成、条目、标注口径与存放格式**，保证：

1. **同口径**：V-06（P1 端到端 demo）与 P2 回归使用同一份测试集、同一标注口径，数字可比较
2. **类别覆盖**：六类场景覆盖 PRD 功能需求（售前/售后/多轮 FR-01/FR-02/FR-03、打断 FR-06）
3. **结果可归因**：每条标注"侧重维度"，延迟/同步/质量/稳定性指标可回溯到具体条目

**变更规则**：增删条目须记录在 §6 版本表，语义不变（同口径）；改动预期要点属于口径变更，须同步更新回归报告。

## 4. 标注口径（MUST）

### 4.1 质量评分（口型准确率）

- 评分范围 1-5 整数，5 = 口型与语音高度吻合，1 = 完全对不上
- 评分人：项目本人（后续可加第二人交叉抽样）
- 评分对象：T5 长句 3 条 + T1 抽 2 条，共 5 条固定抽查集（口径变更须登记）

### 4.2 音画同步人工抽检

- 抽检对象：T4 打断 3 条 + T5-02 长句 1 条
- 记录：肉眼观察时差（±ms 估计）+ 与 V-05 脚本测量值对照
- 偏差 > 30ms 时以脚本值为准复查工具（DESIGN §5.4 坑 5：工具校准优先）

### 4.3 同口径回归定义

回归可比较的前提（缺一即不可比）：
1. 同一测试集版本（§6 版本号）
2. 同一环境（GPU 型号/CUDA/依赖版本，见环境记录）
3. 同一脚本入口（eval/ 下回归脚本，不手工操作）

## 5. 存放与命名（MUST）

```
data/
└── testset/
    ├── testset.json          ← 全量条目（机器可读，回归脚本输入）
    └── audio/                ← P1 由 TTS 生成各条音频（V-06 输入）
        ├── t1-01.wav ... t6-03.wav
```

`testset.json` schema：

```json
{
  "version": "1.0",
  "created": "2026-09-01",
  "items": [
    {
      "id": "T1-01",
      "category": "售前单轮",
      "text": "你们家运费怎么算？",
      "expect": "运费政策（满额包邮/按件）",
      "focus": "延迟"
    }
  ]
}
```

- 多轮条目（T3）以 `turns: ["轮1文本", "轮2文本", ...]` 字段表达
- 打断条目（T4）以 `scene` 字段表达场景描述，脚本按场景手工编排
